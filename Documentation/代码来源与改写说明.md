# 代码来源与改写说明

## 为什么需要这份说明

恢复后的二进制代码显示，最初 Demo 不仅使用了参考仓库的动画素材，也以其教学代码为基础实现了玩家移动和敌人 FSM。公开展示时必须准确说明“参考部分”和“本人扩展部分”，避免把教学代码描述为完全原创。

## 与参考实现高度相关的类型

参考 UnityPackage 中含有 `PlayerMovement.cs`、`FSM.cs`、`IState.cs` 和一个集中定义全部敌人状态的 `IdleState.cs`。恢复构建中对应以下类型：

- `IState`、`StateType`、`Parameter`、`FSM`
- `IdleState`、`PatrolState`、`ChaseState`、`ReactState`
- `AttackState`、`HitState`、`DeathState`
- `StateMachine.PlayerMovement`

本仓库没有直接复制参考包文件，而是在保留 Unity 场景所需类名和序列化字段名的前提下，对这些类型进行了重新组织：

- 增加只读 `CurrentState` 和明确的 `RequestHit` 入口。
- 集中状态边界判定到 `StateGuards`，统一处理空引用和错误配置。
- 为状态转换增加优先级和提前返回，避免同一帧连续转换。
- 将 Animator 初始化提前到 `Awake`。
- 修复死亡重复销毁、失去目标后空引用等问题。
- 保留连击扩展、攻击位移补偿、顿帧和震屏接口，并补充中文注释。

这部分应在面试中描述为：“基于教学 FSM 做了项目化改造和缺陷修复”。

## Demo 中的扩展代码

以下模块未出现在指定参考 UnityPackage 中，是 Demo 在教学基础之上的功能扩展：

- `AttackSense`：命中顿帧与摄像机震动。
- `Enemy`、`PlayerHealth`、`HealthBar`、`Monsterset`：伤害、击退、死亡和 UI。
- `CamreaFollow`：带边界的相机跟随。
- `DoortoNextScene`、`Sign`、`TreasureBox`：关卡与交互。
- `MainMenu`、`PauseMenu`、`InitButton`、`ChatController`：菜单和 UI。

恢复只能证明这些类型存在于本人构建包中，无法替代原始 Git 提交历史作为独立创作时间证据。因此仓库采用“恢复并整理”而不是“完整原始源码”的表述。
